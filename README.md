* Тухай

Энэ төсөл нь [SauceDemo](https://www.saucedemo.com) веб сайт дээр Playwright ашиглан бичсэн UI автомат тестүүдийг агуулна. Нийт 3 үндсэн тестийг бичсэн: амжилттай нэвтрэх, амжилтгүй нэвтрэх (алдааны мессеж шалгах), болон нэвтэрсний дараах үйлдэл (бараа сагслах). Тестүүд нь Chromium, Firefox, WebKit гэсэн 3 браузер дээр зэрэг ажилладаг.

* Playwright ба Selenium-ийн харьцуулалт

Энэ лабораторийн ажлын явцад Playwright-ийг практикт туршиж үзээд Selenium-тэй харьцуулахад дараах ялгаанууд илт мэдрэгдлээ.

Юуны түрүүнд, Playwright нь суулгах, тохируулахад маш хялбар байсан - ганцхан `npm init playwright@latest` командаар браузерууд, тохиргооны файл, жишээ тест бүгд автоматаар бэлэн болсон. Selenium-д ингэж нэг командаар бүгдийг бэлдэх боломжгүй, WebDriver-ийг тус тусад нь татаж, хувилбарыг браузертай тохируулах шаардлагатай байдаг гэдгийг мэднэ.

Хамгийн их анзаарагдсан зүйл бол auto-waiting механизм байлаа - Selenium-д элемент ачаалагдахыг хүлээхийн тулд `WebDriverWait` бичих шаардлагатай байдаг бол Playwright үүнийг өөрөө автоматаар хийдэг тул код илүү цэвэрхэн, богино болсон.

Locator-уудын хувьд Playwright-ийн `getByRole`, `getByPlaceholder` зэрэг нь хэрэглэгчийн харж буй зүйл дээр суурилдаг тул илүү тогтвортой бөгөөд унших боломжтой байлаа. Гэхдээ SauceDemo дээр `getByTestId()` ашиглахад алдаа гарсан - учир нь энэ сайт `data-testid` биш харин `data-test` атрибут ашигладаг байсан тул `page.locator('[data-test="..."]')` гэж CSS selector-оор шууд бичих шаардлагатай болсон.

XPath-аас яагаад зайлсхийсэн бэ гэвэл, XPath нь HTML-ийн бүтэц (ямар div дотор ямар элемент байгаа гэх мэт) дээр шууд суурилдаг тул хуудасны дизайн бага зэрэг өөрчлөгдмөгц (жишээ нь нэмэлт wrapper нэмэгдэхэд) тэр даруй эвдэрдэг. Харин getByRole, getByPlaceholder зэрэг нь хэрэглэгч дэлгэц дээрээ юу харж, юу дээр дарж байгаа дээр л суурилдаг тул дизайны дотоод бүтэц өөрчлөгдсөн ч тест эвдрэхгүй, илүү тогтвортой байдаг.
Trace Viewer бол Playwright-ийн хамгийн хүчтэй тал гэдгийг мэдрэв - тест бүрийн алхам, screenshot, network хүсэлт, timing-ийг нэг дор харах боломжтой нь дебаг хийхэд асар их цаг хэмнэдэг. Selenium-д ийм built-in хэрэгсэл байдаггүй, өөрөө screenshot logic бичих эсвэл гуравдагч талын хэрэгсэл ашиглах шаардлагатай.

Codegen хэрэгслийг туршихад хэрэглэгчийн үйлдлийг автоматаар кодруу хөрвүүлдэг нь эхлэл болгоход хэрэгтэй ч, generate хийсэн код нь `expect()` шалгалт агуулаагүй, зөвхөн үйлдлийг л бичдэг байв. Иймд codegen-ийг зөвхөн selector олох, эхлэлийн код бэлдэхэд ашиглаж, бодит assertion-уудыг гараар нэмэх нь зөв арга гэдгийг ойлгов.

Ерөнхийдөө Playwright нь орчин үеийн вэб апп тестлэхэд илүү хурдан, тохиромжтой, дебаг хийхэд илүү хялбар хэрэгсэл гэдгийг энэхүү лабораторийн ажлаар мэдэрлээ.

3. Бараа сагслах: - нэвтэрсний дараа бараа сагсанд нэмж, сагсны тоо болон агуулгыг шалгана
